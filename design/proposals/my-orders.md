# 제안: 내 주문 (개인 페이지)

상태: 확정 전. 시안 `design/screens/MyOrders.dc.html` (속성 `view`: 주문 많음, 비어 있음, 허락 기다림, 멈춘 용. `species`로 숲, 물, 꽃, 별). 지금 `/orders`는 TopBar와 ListRow뿐이라 시안이 없다 (`docs/wiki/components/web.md`의 디자인 공백).

## 화면에 있는 것
1. 위 줄: 뒤로, "내 주문", 오른쪽에 종별 용이 (누르면 대화).
2. 30일 배달비: 쓴 돈을 크게, "/ 내 30일 한도", 막대, 오른쪽에 "이번 달 N원 아꼈어요".
3. 거르기 칩: 전체, 배달 완료, 멈춤.
4. 주문 줄: 날짜, 상태 칩(배달 완료, 멈춤, 허락 기다리는 중), 가게, 메뉴, 금액, 버튼 둘(재주문, 맛 평가). 구분은 1px 선이고 카드로 감싸지 않는다 (D-17).
5. 빈 화면: 용이 한 줄 "아직 시킨 게 없어용. 뭐 먹고 싶어용?"과 버튼 하나.
6. 멈춘 용: 바탕이 Frozen과 같은 회색, 재주문은 꺼지고 아래에 "용이가 자고 있어용"과 깨우기.

## 왜 이렇게
- 배민 주문내역처럼 "다시 시키기"가 한 번에 닿는 것이 핵심이다. 시켜용은 거기에 내 30일 한도를 맨 위에 두어, 다시 시키기 전에 얼마 남았는지 보이게 했다.
- 새 정보는 늘리지 않았다. 숫자는 Main, Wallet에서 쓰던 것과 같은 모양이다.
- 허락 기다리는 줄만 강조색 버튼(확인하기)이라 눈이 먼저 간다.

## 주인님이 고를 것
1. 재주문: 누르면 바로 확인 카드(견적)로 갈지, 대화로 보내 용이가 "또 시킬까용?" 하고 물을지. 시안은 앞쪽을 가정했다. 결제는 어느 쪽이든 확인 버튼에서만 일어난다.
2. 합계 기준: "30일 배달비"(한도와 같은 창, 시안) 또는 달력 기준 "이번 달". 30일 한도와 나란히 놓으려면 30일이 맞다.
3. 맛 평가를 이 목록에서 바로 줄지(시안, 세 가지를 누르는 작은 시트) 도착 화면에서만 줄지.
4. 칩 개수: 시안은 3개. "허락 기다림"을 따로 칩으로 둘지, 맨 위 줄로만 둘지.
5. 입구: Main 위 줄의 주문 내역 버튼 하나(지금과 같음) 또는 Wallet에도 줄을 하나 더.
6. 마이페이지(프로필, 설정 모음)는 이번엔 만들지 않았다. 설정은 이미 Wallet에 있어 중복이다. 필요하면 별도 제안.

## 코드가 필요한 것
이미 있음 (`GET /api/orders`, `OrderView`, `BudgetView`): 가게(`store`), 메뉴(`items`), 금액(`amount`), 상태(`status`로 배달 완료, 멈춤, 허락 대기 가르기), 30일 쓴 돈과 한도(`chainUsed`, `myPeriodicLimit`), 멈춤 여부(`frozen`), 맛 평가 보내기(`POST /orders/:id/rating`), 종(`GET /me`).

없음:
- 주문 시각: `OrderView`에 없다 (web.md에도 같은 지적). 날짜 줄에 필요하다.
- 맛 평가의 현재 값: 목록에 없다. "또 먹을래" 표시에 필요하다.
- 이번 달 아낀 돈: 숫자가 Wallet 쪽에서만 온다 (목록 화면이 한 번 더 부름).
- 거르기: `ORDER_LIST_MAX` 20개 안에서 클라이언트가 한다. 더 오래된 주문은 페이지 넘김이 필요하다 (주인님이 필요하면).
- 재주문: 새 견적을 같은 메뉴로 만드는 길 (`POST /orders`는 가게와 메뉴 id가 필요하고, `OrderView.items`에는 id가 없다).
- UI: 주문 줄, 상태 칩, 한도 요약은 `packages/ui`에 새 컴포넌트와 위키 문서가 필요하다 (D-18).
