# 시켜용 유저 플로우

화면 파일은 `screens/`, 결정은 `docs/_research/decisions.md`. 사용자 화면에는 블록체인 말을 쓰지 않고, 아래 "뒤에서" 칸에만 쓴다.

## 전체 흐름

```mermaid
flowchart TD
  Z["로딩: 용이를 깨우는 중"] -->|세션 없음| A
  Z -->|세션 있음| F
  A["시작: 이메일로 시작하기"] --> A2["이메일, 패스키 설정과 지갑 생성 (파우치 금고)"]
  A2 --> B[본인 인증: 카카오톡]
  B -->|실패, 취소| B
  B --> C[알 고르기(숲, 물, 꽃, 별), 이름 짓기]
  C --> D[부화 중 1~3분]
  D -->|실패| D2[다시 시도]
  D2 --> D
  D --> E[한도 정하기: 한 번에, 30일에, 체험용 용돈 받기]
  E --> F[대화: 점심 시켜 줘]
  F --> G[추천 2~3곳]
  G --> H{한도 안인가}
  H -->|예| I[주문 확인 시트]
  H -->|한 번에 쓸 돈 초과| L[한도 초과]
  H -->|처음 보는 가게| M[주인 허락 카드]
  H -->|30일 한도 다 씀| N[30일 한도 다 씀]
  M -->|허락| I
  L -->|한도 올리기| O[변경 카드, Face ID]
  O --> I
  L -->|다시 고르기| G
  I -->|시키기| J[조리 중]
  J --> K[배달 중]
  K --> P[도착, 맛 평가]
  P --> F
  I -->|다시 고를래| G
  J -->|가게 거절| R[환불, 대화로 알림]
  F -.->|말로 한도 바꾸기| O
  F -.->|진행 중인 주문 카드| J
  F -.->|주문 내역 버튼| Q[주문 상세]
  F -.->|용이 멈춰| S[용이 멈춤]
  S -->|깨우기| F
  F -.->|설정| W[용이 용돈]
  W -->|용이 모습| LK[용이 모습 바꾸기]
  LK -->|이 모습으로 바꾸기| W
```

## 단계별

| # | 화면 | 사용자가 하는 일 | 앱과 서버 | 뒤에서 (체인) | 예외 |
| --- | --- | --- | --- | --- | --- |
| 0 | Splash | 기다림 (화면을 누르면 넘어감) | 세션 확인. 세션 있으면 Main, 없으면 Start. 1초 안에 끝나면 바로 넘긴다 | 없음 | 움직임 줄이기 설정이면 애니메이션 끔 |
| 1 | Start | "이메일로 시작하기" 하나 (D-29). 이메일 코드와 패스키(Face ID) 화면은 파우치 금고가 그린다 | API(Nest) auth가 파우치 결과(bridge)를 검증하고 쿠키 세션 발급. 앱 키는 서버에만 | 가입이면 사용자 스마트 지갑이 생긴다(파우치. 체인에 지갑 컨트랙트가 가입 때 배포되는지 첫 거래 때 배포되는지는 추론 단계, S14. 가스는 앱 대납) | 로그인 취소: 그대로 머묾. 원래 요청을 보존 |
| 2 | Verify | 카카오톡으로 본인 인증 | 인증 결과만 받음, 원문 저장 안 함 | 주인 **파우치 스마트 지갑 주소**를 recipient로 KYC 증명(EAS, 카카오 스키마)을 받는다. PCL EAS 검사가 실행 주체(`op.From`, 스마트 지갑)를 본다 (미확인, 호재 님 전달: maroo `x/pcl/keeper/policy/eas.go`, 코드 미열람). kyc-testnet이 스마트 지갑 주소를 받는지는 미확인, Q-19 | 실패: 다시 시도. 체험판 Mock KYC로 바뀌면 같은 버튼 |
| 3 | Name | 알 고르기(숲, 물, 꽃, 별), 이름 짓기 | 이름과 종 저장 | 없음 | 이름 비면 버튼 비활성 대신 안내 |
| 4 | Hatch | 기다림 (닫아도 됨) | 에이전트 생성 상태 폴링, 끝나면 알림 | 에이전트 지갑 생성, 8004 등록, TransferLimit 10,000(처음 제안값) 기록 | 실패: "다시 깨우기" 버튼, 운영자 알림. TransferLimit 기록 전에는 주문 막음 |
| 5 | Budget | 한 번에 쓸 돈과 30일에 쓸 돈 정하기, 체험용 용돈 받기 (D-31) | 내 30일 한도 저장 (서버) | 한 번에 쓸 돈이 처음 제안값과 다르면 8004 TransferLimit 다시 기록. 체험용 용돈: faucet 또는 운영자 지갑에서 주인 지갑으로 | 기록이 끝나기 전에는 주문 막음 |
| 6 | Main | "점심 시켜 줘" | LLM이 읽기 도구로 예산, 기록, 날씨 확인. 서버가 추천 점수 계산 | 30일 사용량 읽기 | 내 30일 한도 70%, 90%에서 잔소리 한 번씩, 넘으면 서버가 막음 (D-31). 진행 중인 주문이 있으면 예산 카드 아래 상태 카드(접수, 조리 중 → Done, 배달 중 → Tracking). 상단 영수증 버튼은 주문 내역 |
| 7 | Confirm | 메뉴 확인 후 "9,000원 시키기" | `place_order`는 견적만. 버튼이 `POST /api/orders/:id/confirm` | 에이전트 지갑에 float 즉시 충전, `placeOrder{value}` (건당 한도와 30일 한도를 PCL이 검사) | 가격이 바뀌면 다시 확인. 실패 시 자동 재시도 안 함 |
| 8 | Done | 기다림 | 주문 접수, 가게 알림. 화면은 낙관적으로 바로 넘어감 | `OrderPlaced` 이벤트를 인덱서가 확정 | 가게 3분 안에 접수 안 하면 자동 거절, 환불 |
| 9 | Tracking | 기다림, 지도 보기 | 1단계 목 가게는 서버 타이머, 2단계는 배달대행 위치 | 없음 | 지연되면 도착 시간 갱신, 드래곤이 알림 |
| 10 | Arrived | 맛 평가 | 평가를 추천에 반영, 아낀 돈 계산 | 없음 | |
| 11 | Receipt | 자세히 보기 펼침 | 영수증 규칙 목록 | 결제 기록 번호, 통과한 정책 이름, 탐색기 링크 | |
| 12 | Blocked | "한 번에 45,000원으로 올리고 시키기" 또는 다시 고르기 (D-31) | 서버 사전 검사가 먼저 막음 (데모는 체인까지 보냄) | 데모: `ExceededAgentTransferLimit` revert | |
| 13 | LimitChat | 말로 "5만 원까지 올려 줘", Face ID | LLM은 변경 카드만 만든다. 확정은 버튼과 재인증 | 한 번에 쓸 돈이면 8004 TransferLimit 50,000 기록 | 내리기와 멈춤은 재인증 없이 바로 (D-31) |
| 14 | Cap | 알림 받기 | 리셋 시각 표시 | `ExceededPeriodicVolume`의 `resetAt` | 모두에게 같은 30일 상한은 주인도 못 바꿈. 내 30일 한도에서 막혔으면 올리기 버튼 (D-31) |
| 15 | Wallet | 잔액, 한도 확인, 채우기, 스위치 | 자세히 보기 스위치는 기기 설정 | 주인 지갑, 에이전트 지갑 잔액 읽기 | |

## 데모에서 보여 줄 순서 (약 5분)
1. 시작에서 부화까지 빠르게 (미리 만든 계정이면 6번부터)
2. 6 → 7 → 8 → 9 → 10: 정상 주문과 기다림
3. 12 → 13: 한도 초과, 말로 올리고 다시 시키기
4. 14: 30일 한도 (데모 프로필 1시간 주기)
5. 키 유출 비교 화면 (DEMO_MODE, 시안 없음, tech-spec 9.3)
6. 17: 멈추고 돌려받기
7. 11: 자세히 보기를 켜서 체인이 실제로 검사한 것 보여 주기
