# 개발 루프: 커밋 하나, 검증 하나 (2026-11-19, 호재 님 요청)

구현은 작은 커밋 단위로 나눠서 하고, 커밋마다 만든 쪽과 다른 검증 에이전트가 까다롭게 본다. 통과할 때까지 고치고 다시 본다.

## 루프
```
계획한 커밋 하나 구현
  → python3 -I scripts/verify.py --precommit 으로 스스로 확인 (미추적 파일 포함, 커밋 메시지 검사 없음)
  → 커밋 (한 가지 일만)
  → commit-verifier 에이전트를 새로 띄운다 (범위, 하려던 일만 전달. 작성자의 결론은 주지 않는다)
  → VERDICT: FAIL 이면 지적 항목을 고쳐 별도 수정 커밋 fix(<범위>): 검증 피드백 반영
       → 같은 기준으로 다시 검증 (범위: 원래 커밋의 부모..수정 커밋, --msg-range 는 이전 라운드 HEAD..수정 커밋, 이전 피드백 함께 전달)
  → VERDICT: PASS 이면 다음 커밋으로
```
- 수정 커밋도 나눠서 쌓는다. 이미 만든 커밋을 amend하거나 히스토리를 고치지 않는다. 그래서 재검증 때 커밋 메시지 검사는 새로 쌓은 커밋에만 건다 (`--msg-range`). 지난 커밋 메시지의 실수는 기록으로 남긴다.
- 검증 중에 다음 커밋이 먼저 쌓였으면, 재검증 때 검증 대상 커밋 목록(원래 커밋과 수정 커밋 SHA)을 명시해서 넘긴다. 사이에 낀 다른 커밋은 각자의 검증에서 본다.
- 같은 커밋에서 3라운드가 지나도 FAIL이면 멈추고 사람(호재 님)에게 지적 목록과 막힌 이유를 보여 준다. 검증자와 작성자의 해석이 갈리는 지점(명세가 모호함)은 `log/open-questions.md`에 올린다.
- 검증자는 대상 커밋의 분리된 worktree에서 돌린다. 그래서 검증하는 동안 작성자는 다음 커밋을 만들 수 있다. 단 FAIL이면 다음 커밋보다 수정 커밋이 먼저다.
- 검증자는 매번 새로 띄운다. 앞 라운드 검증자의 결론에 묶이지 않게 하려는 것이다. 이전 피드백 목록만 넘긴다.
- MINOR만 남으면 통과다. MINOR는 다음 커밋에서 고치거나 무시 사유를 남긴다.
- **검증 범위는 그 커밋이다** (2026-11-19 호재 님 결정). 막는 것은 그 커밋의 변경이 틀렸거나 새로 만든 문제, 그리고 범위와 상관없이 돈, 비밀, 절대 규칙, 빌드와 테스트 실패다. 다른 컴포넌트 설계 확장, 기존 문제, 게이트 정규식의 새 우회는 MINOR(후속)로 기록만 한다. 자세한 기준은 `.claude/agents/commit-verifier.md` "범위".

## 예외 표식
- 게이트는 주석을 걷어낸 코드만 본다 (문자열과 템플릿 안의 `//`는 코드로 본다). 예외: `@ts-ignore`, `eslint-disable`은 주석 안에서 찾는다.
- 범위 검증은 범위 끝 커밋이 체크아웃된 상태에서만 돈다 (아니면 exit 2). 검증자는 대상 커밋의 worktree에서 돌린다.
- 규칙에 걸리지만 정당한 줄은 그 줄이나 바로 윗줄에 `verify-allow: <규칙> <사유>`를 단다. 파일 전체를 판단하는 규칙(페이지 조립, 컨테이너, 컨트롤러의 D18)은 파일 어디에든 `verify-allow: D18 <사유>`가 있으면 넘어간다. 예: `// verify-allow: R4 비율 표시, 금액 아님`. 사유가 없으면 인정하지 않는다. 검증 에이전트는 사유가 타당한지 본다.
- LLM 도구 정의는 `apps/api/src/modules/llm/tools/` 안에만 둔다. 게이트는 거기서 도구 이름을 뽑아 허용 목록과 비교하고, 허용 목록 8개(D-21로 `propose_limit_change` 추가)를 모두 적은 화이트리스트 비교 테스트를 요구한다 (`testing.md` "도구 화이트리스트 자동 비교"). 정적 검사는 보조이고 근거는 그 테스트다.

## 규칙을 고칠 때
- 게이트가 틀리게 막으면(오탐) 게이트를 고치는 커밋을 따로 만든다 (`chore(verify): ...`). 규칙을 피하려고 코드를 꼬지 않는다.
- 새 규칙이 생기면 이 표, verify.py, 자체 테스트 `scripts/verify_test.py`(`pnpm verify:test`, 위반 예와 정상 예)를 같은 커밋에서 고친다. 자체 테스트가 실패하면 게이트를 믿지 않는다.
