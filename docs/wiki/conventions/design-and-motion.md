# 디자인, 문구, 움직임, 성능

화면 기준은 저장소 `design/` (시안 사본, 유저 플로우, 토큰). 결정은 decisions D-17.

## 반드시 지킬 규칙 (MUST)

### 화면 문구
- 사용자 화면에 블록체인 말을 쓰지 않는다. 아래 표대로 바꾼다. 원래 말은 "자세히 보기" 안에서만 쓴다.

| 쓰지 않는 말 | 쓰는 말 |
| --- | --- |
| 지갑, 주소, 시드 문구 | 용돈, 용이 주머니 (주소는 보여 주지 않음) |
| OKRW, 토큰 | 원 |
| 트랜잭션, 해시, 탐색기 | 결제 기록 (자세히 보기 안) |
| 가스비 | 쓰지 않음 (페이마스터 또는 서버가 냄) |
| KYC, attestation | 본인 인증 |
| 에이전트 등록, 8004 | 용이 신분증 |
| 정책, PCL, revert | 용이 규칙, 한도에 걸렸어요 |

- 체인의 성질은 결과로 말한다: "이 한도는 용이도, 시켜용도 못 바꿔요." 과장 금지 규칙(CLAUDE.md 11)은 그대로.
- 드래곤 말은 한 줄이나 두 줄. 말투 "~용". 시스템 문구(버튼, 라벨)에는 "~용"을 쓰지 않는다.

### AI 슬롭 금지 (2026-11-19 호재 님 피드백)
- 체크리스트 카드(체크 아이콘 + 항목 여러 줄)를 쓰지 않는다.
- 아이콘 달린 안내 박스(정보, 경고 색 배경)를 쓰지 않는다.
- 설명 문단과 안심시키는 문구를 쓰지 않는다. 숫자를 크게, 드래곤 한 줄, 버튼으로 끝낸다.
- 모든 것을 카드에 넣지 않는다. 구분은 여백이나 1px 선으로.
- 그라데이션, 장식 그림자, 이모지, 반짝이 AI 아이콘 금지.

### 시각
- 값은 `design/tokens.json`에서만 가져온다. 화면 코드에 색 코드를 직접 쓰지 않는다.
- 한글은 `word-break: keep-all`(RN은 줄바꿈 전략 설정), 본문 자간 -0.01em.
- 금액은 고정폭 숫자, 표기는 "9,000원" 하나. 원 아래 버림, 음수 표기 같은 세부 규칙은 `code-style.md` 금액 항목.
- 터치 영역 44 이상, 대비 4.5:1 이상, 아이콘만 있는 버튼에는 접근성 라벨.

### 움직임 (토스 수준의 부드러움)
- 애니메이션은 Motion(framer-motion)으로 `transform`과 `opacity`만 움직인다(합성 레이어). `top`, `height` 같은 레이아웃 속성은 애니메이션하지 않는다. 화면 전환은 View Transitions.
- 누름: 0.97 스프링 (값은 `packages/ui/src/base/press.ts`의 `PRESS`, `PRESS_SPRING` 하나만 쓰고, 누르는 버튼은 base `Button`, `Chip`, `Switch`만 만든다. 테스트가 tokens.json `motion.press`와 맞는지 본다). 시트: 드래그로 닫히는 바텀시트(`Sheet` 컴포넌트, Motion 드래그). 금액 변화: 자리별로 굴러가는 숫자(`Amount`).
- 화면 전환 220ms 안팎, 감속 곡선. 의미 없는 등장 애니메이션(모든 카드 페이드 업) 금지.
- 진동(`navigator.vibrate`, 지원 기기만)은 결제 완료, 한도 변경, 도착, 막힘에만. iOS 사파리는 지원하지 않는다.
- 시스템 "동작 줄이기"가 켜지면 이동 없이 페이드만.

### 성능
- 결제 버튼은 낙관적 UI: 누르는 즉시 조리 중 화면으로 넘어가고, 체인 확정은 뒤에서 받는다. 실패하면 되돌리고 드래곤이 이유를 말한다.
- 로딩은 실제 화면 모양의 스켈레톤. 빈 스피너만 띄우지 않는다.
- 다음 화면 데이터는 미리 불러 둔다 (TanStack Query prefetch).
- 이미지는 `next/image`, 글꼴은 자체 호스팅 CSS(npm `pretendard` 동적 서브셋, `@fontsource/gowun-dodum`). 토큰의 글꼴 이름을 지키려고 `next/font`는 쓰지 않는다 (web.md). 첫 화면 JS를 줄이려고 움직임 없는 부분은 Server Component.
- 대화 스트리밍은 토큰마다 렌더하지 않고 프레임 단위로 묶는다.
- 출시 기준: 모바일 기기에서 60fps, Lighthouse 모바일 성능 90 이상, INP 200ms 이하 (프로덕션 빌드로 측정).

## 부드러움 기준 (D-23, 토스 수준)
화면 조립 뒤 UX 다듬기 단계에서 화면마다 이 표를 채운다. 하나라도 어기면 그 화면은 끝난 것이 아니다.

| 항목 | 기준 | 확인 방법 |
| --- | --- | --- |
| 누름 반응 | 100ms 안에 눈에 보이는 변화 | 실기기 화면 녹화, Performance 패널 |
| 서버를 기다리는 동작 | 낙관적 UI, 실패 시 되돌리고 용이가 이유를 말함. 결제 확정은 예외(확인 버튼 뒤 "진행 중") | 네트워크 느리게(Slow 4G)로 시험 |
| 전환 | 60fps, transform과 opacity만, 화면 사이 View Transitions 또는 공유 요소 | Performance 패널 프레임 |
| 시트 | 끌어 닫기, 스프링(motion.sheet) | 실기기 |
| 기다림 | Skeleton, 레이아웃 밀림 없음(CLS 0.0x), 스피너는 1초 넘을 때만 | Lighthouse CLS, 느린 네트워크 |
| 금액 | 자리별 굴러가기(motion.number 400ms) | 눈으로, 스토리 |
| 미리 받기 | 다음 화면 데이터 prefetch, 뒤로 가기 즉시 | 네트워크 탭 |
| 입력 | 한글 조합 끊김 없음, 키보드가 입력칸과 버튼을 가리지 않음 | iOS Safari, Android Chrome |
| 동작 줄이기 | 위치 이동 없이 페이드 | OS 설정 켜고 확인 |

## 하지 말 것 (MUST NOT)
- 시안에 없는 설명 문구를 덧붙이지 않는다.
- 시안의 색, 간격을 "비슷하게" 바꾸지 않는다. 바꾸려면 캔버스부터 고친다.
